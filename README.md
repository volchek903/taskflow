# Taskflow: Telegram Widget + Mini App

Проект запускает в одном Python-контейнере Telegram-бота, API, SQLite и собранный React-фронтенд. Команда `/start` отправляет персональный HTML Widget с назначенными пользователю задачами. Кнопка под виджетом открывает полный Taskflow как Telegram Mini App.

## Структура

- `frontend/` — весь исходный React/Vite-проект и legacy-версия.
- `bot/` — Bot API-клиент, Widget 10.4 и HTTP-сервер фронтенда.
- `bot/db.py` — схема SQLite и операции с пользователями, проектами, участниками, задачами и приглашениями.
- `bot/auth.py` — проверка подписи Telegram Mini App `initData`.
- `main.py` — единая точка входа.
- `Dockerfile`, `compose.yaml`, `Caddyfile` — сборка, запуск и HTTPS.

## Запуск в Docker

1. Создайте бота через `@BotFather` и получите токен.
2. Направьте A/AAAA-запись вашего домена на сервер. Порты 80 и 443 должны быть доступны извне.
3. Создайте конфигурацию:

   ```sh
   cp .env.example .env
   ```

4. Укажите в `.env` настоящий `BOT_TOKEN`, имя бота без `@` в `BOT_USERNAME`, `DOMAIN` и тот же домен с `https://` в `WEBAPP_URL`.
5. Запустите:

   ```sh
   docker compose up -d --build
   docker compose logs -f taskflow
   ```

Caddy автоматически запросит TLS-сертификат. После запуска отправьте боту `/start`. Для локального просмотра фронтенд также доступен на `http://127.0.0.1:8080`, но Telegram принимает для Mini App только публичный HTTPS URL.

## Команды Telegram-бота

- `/start` и `/today` — персональный виджет задач на сегодня, кнопка открывает страницу «Сегодня».
- `/projects` — виджет проектов с участниками, кнопка открывает список проектов.
- `/inbox` — виджет входящих приглашений, кнопка открывает «Входящие».
- `/settings` — виджет профиля и статистики, кнопка открывает настройки.

Команды автоматически регистрируются через `setMyCommands` при запуске контейнера. Slash-палитры внутри Mini App нет.

SQLite хранится в Docker volume `taskflow_data` по пути `/data/taskflow.db`, поэтому пересборка контейнера не удаляет данные. Удаление volume удалит базу без возможности восстановления.

## Пользователи и совместная работа

- Пользователь создаётся или обновляется из подписанного Telegram `initData`.
- Владелец проекта может открыть или закрыть присоединение новых участников.
- Общая ссылка ведёт через deep link бота, чтобы Telegram передал Mini App подписанные данные пользователя; короткий код можно ввести вручную. Оба способа работают, пока присоединение открыто.
- Персональное приглашение создаётся по `@username` или Telegram ID. Пользователь должен хотя бы один раз запустить Taskflow, чтобы появиться в локальной базе.
- Задачу можно назначить любому участнику выбранного проекта.
- Widget показывает актуальный снимок соответствующего раздела на момент выполнения команды; изменения выполняются в Mini App.

## Локальная разработка

Telegram-авторизация недоступна в обычной вкладке браузера. Только для локальной разработки добавьте в `.env`:

```env
ALLOW_DEV_AUTH=true
```

В production оставляйте `ALLOW_DEV_AUTH=false`, иначе локальный отладочный пользователь сможет обращаться к API без Telegram-подписи.

Запуск без Caddy на Windows:

```sh
docker compose up -d --build taskflow
```

Тесты модели данных:

```sh
python -m unittest discover -s tests -v
```

## Важно про Widget 10.4

Widget находится прямо внутри сообщения, но по правилам Telegram не имеет доступа к сети и не может загрузить React-сайт или iframe. Поэтому в сообщении показывается персональное компактное превью выбранного раздела, а полный сайт открывается нативной Web App-кнопкой. Сейчас Telegram разрешает `sendWidget` в production только в личных чатах; в группе бот попросит открыть личный чат.

Если клиент Telegram ещё не поддерживает Widget или API отклонит его, бот автоматически отправит обычное сообщение с той же Mini App-кнопкой.
